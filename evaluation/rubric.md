## 案例结构

`cases.jsonl` 每条：
```json
{"case_id": "R1-01", "category": "recovery",
 "setup": {"memory_seed": [...], "context": "..."},
 "query": "...",
 "checks": ["<可判定的检查点>"],
 "designed_parts": "标注哪些是人工设计情境（非真实数据）"}
```

四类各 3 例：`recovery`（跨会话恢复）、`supersede`（失效记忆处理）、`honesty`（不确定性保留）、`multirun`（跨运行任务）。

## 评分规则（每例 0/1 判定 + 违规倒扣）

| 检查维度 | 通过标准 | 权重 |
|---|---|---|
| 任务正确率 | 按 checks 逐项判定，全部命中=1，否则 0 | 主指标 |
| 过时记忆误用 | 输出引用了 setup 中已标 superseded/rejected 的内容 → 该例 0 分并计入误用率 | 倒扣项 |
| 引用支持 | 输出中的引用均有对应有效证据；编造 work_id/evidence_id → 0 分 | 倒扣项 |
| 不确定性处理 | honesty 类：明确指出缺口/冲突，不给无依据结论 | 主指标 |
| 状态一致性 | multirun 类：两段运行后状态可重建、无重复写入 | 主指标 |
