# 研究协议（冻结版 v1.0）

冻结日期：2026-10-17。本协议由 `EXECUTION_PLAN.md` §2、§4、§5 抄录并冻结，是检索、筛选、去重、证据与记录的执行依据。修改协议须在 `docs/decisions.md` 记录理由与影响，并更新本文件版本号。

## 1. 研究问题（RQ，冻结）

核心问题：智能体如何从持续交互中保留有用经验，在信息变化时正确更新记忆，并在后续任务中可靠地使用这些记忆？

- **RQ1 定义与边界**：长期记忆包含哪些信息和机制？它与上下文历史、静态知识检索、参数知识有什么关系？
- **RQ2 组织与使用**：写入、组织和检索方法如何影响信息可用性、任务表现和成本？
- **RQ3 更新与遗忘**：如何处理信息变化、时间条件、冲突、过时记忆和必要的删除？
- **RQ4 可靠性**：错误摘要、错误反思或来源混淆如何进入记忆并影响后续决策？现有方法怎样发现和控制这些问题？
- **RQ5 评测**：基准和实验是否真正考察跨会话记忆、更新能力和长期任务表现？不同结果能否公平比较？

## 2. 检索截止日（冻结）

**主检索截止日：2026-10-17。** 此日期后新发表的文献不进入主检索；提交前做一次增量检索并单独记录新增范围与截止日。

## 3. 纳入标准

1. 以大语言模型为核心，在多个交互回合、会话或任务之间保存并复用外部信息的系统。
2. 记忆内容可以是事实、交互事件、任务状态和程序性经验，但需明确其来源与用途。
3. 覆盖记忆写入、筛选、压缩、组织、检索、更新、遗忘及评测。
4. 与上述问题直接相关的方法论文、实证分析、评测基准和少量高质量综述。
5. 以文本任务为主；其他模态只有在能回答核心研究问题时纳入，并说明原因。
6. 时间范围 2020-01-01 至检索截止日；更早的理论/方法文献作为背景补充，不自动视为现代大模型记忆系统。

## 4. 排除标准（使用稳定理由码）

| 理由码 | 含义 |
|---|---|
| `out_of_scope` | 不满足纳入标准（无 LLM 记忆机制或与 RQ 无关） |
| `no_memory_mechanism` | 泛智能体文章，缺少清晰记忆机制或评测关系 |
| `non_academic` | 博客、产品文档、代码仓库（可作实现参考，不计入 30 篇） |
| `duplicate_version` | 同一研究的另一版本（预印本/会议/期刊归并为一个 work_id） |
| `fulltext_unavailable` | 正文无法合法获取（保留为候选，不用于支撑核心结论） |
| `insufficient_content` | 正文可得但缺少支撑所需结论的内容 |

## 5. 版本去重与身份核验

1. 优先匹配 DOI、arXiv ID、出版方标识；无唯一标识时组合题名+首作者+年份人工复查。
2. DOI 归一化：小写、去除 `https://doi.org/` 或 `https://dx.doi.org/` 前缀。
3. arXiv ID 归一化：去除版本后缀（`2310.08560v2` → `2310.08560`）；新版 arXiv ID 与旧版 `cs.XX/YYMMNNN` 分别按原样归一。
4. 同一研究的不同版本共享 `work_id`，各来源记录保留独立 `source_id`。
5. 正式版与预印本并存时记录主引用版本；证据定位绑定实际读取版本（预印本页码不写成正式版页码）。
6. 元数据缺失标缺失，禁止由模型补造；发现撤稿/勘误必须记录，不静默沿用。

## 6. 检索来源（≥2 个不同覆盖范围）

| 来源 | 角色 | 记录要求 |
|---|---|---|
| OpenAlex API | 主源：关键词检索 + 引文图谱 | `mailto` 礼貌池参数；cursor 分页 |
| arXiv API | 第二源：预印本检索 + 全文获取 | ≥3s 请求间隔（实测限流）；退避重试 |
| Semantic Scholar API | 增益源：受 429 限流影响 | 退避重试，失败不阻塞 |
| arxiv.org / ar5iv HTML | 全文获取通道 | 记录 URL 与访问日期 |

每次检索（含失败与未完整分页）写入 `data/search_runs.jsonl`。

## 7. 数据记录格式（六个 JSONL 主文件）

字段见 `EXECUTION_PLAN.md` §5.1；由 `src/litreview_agent/models.py` 的 pydantic 模型做程序验证。原则：

- 稳定标识（`*_id`）、来源、状态、时间四类字段必须保留；未知值留空并注明原因，不用推测补齐。
- 追加写入，不覆盖历史；记忆更新用 `supersedes` 关系链。
- 草稿、模型推测、人工意见与原文证据分别记录，草稿不升级为事实证据。

## 8. 证据成立条件（六要素）

1. 已核验的论文身份与读取版本；
2. 实际查看的原文片段（保留必要上下文）；
3. 可回查定位：PDF 页序与印刷页码 / 章节表号 / HTML 稳定章节标题+URL+访问日期；
4. 用自己的话写出的解释，区分作者结论与本组综合；
5. 适用条件与局限（模型、数据集、对照组、上下文预算、实验任务）；
6. 核验状态：`auto_checked` / `model_assisted` / `human_verified` 分别记录。

数值必须回到原始表格或正文确认指标定义、单位、分母和比较对象；不能靠语言模型"修正"缺失数字。

## 9. 陈述支持等级

- `direct`：单篇原文直接支持；
- `synthesis`：跨论文综合，须保留多份证据和综合理由；
- `hypothesis`：本组提出的可能解释，须明确标识。

来源存在但不支持结论 = 引用错误；缺证据时缩小、改写为有条件判断或删除，不保留强结论再找"看起来相关"的引用。

## 10. 停止规则

1. 数量（≥35 项纳入目标）、RQ 覆盖、主要方法分支均达标，且连续两轮补检未发现新主要类别 → 冻结主检索。
2. 该规则是项目停止条件，不证明覆盖了领域全部研究。
